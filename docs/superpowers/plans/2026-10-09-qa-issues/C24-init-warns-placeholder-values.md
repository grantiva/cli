# Warn when init writes placeholder scheme and simulator values

Severity: ux
Platforms: cli, ios
Found by: CLI-F07 (matrix rows CLI-072)
Binary: grantiva 2.0.1 (commit c8dc86d)

## Expected
In a directory with no project, `init` gives a clear error that no project was found, or writes a documented default
and says which values are placeholders. Source: help: init ("Generate grantiva.yml (iOS) or grantiva-android.yml
(Android) in the current directory.").

## Actual
Exit 0, stderr only `Created grantiva.yml`, and the file holds two guesses (iPhone 16 is absent on Xcode 27 hosts):
```
# Generated by grantiva init — commit this file
scheme: MyApp
# workspace: MyApp.xcworkspace
simulator: iPhone 16
```

## Repro
```
cd $(mktemp -d) && grantiva init; echo rc=$?; cat grantiva.yml
```
Also in fixtures/detect/xcode-only: `simulator: iPhone 16` is written although the scheme is detected.

## Evidence
- findings/evidence/cli/detect/detect.txt ([neither] and [xcode-only] init rows)

## Suspected cause
Sources/GrantivaCLI/InitCommand.swift:52 falls back to `"MyApp"` and :58 hardcodes `simulator: iPhone 16`, with no
warning.

## Acceptance criteria
- Re-running the repro prints on stderr, e.g., `No Xcode project found; scheme "MyApp" is a placeholder. Edit
  grantiva.yml or pass --scheme.` (or refuses without `--scheme`, if that is the chosen behavior).
- The simulator default is a device type installed on the host (newest iPhone from `simctl list devicetypes`), or is
  marked as a placeholder.
- GrantivaCLITests: an init test in an empty temp dir asserts the placeholder warning, and one with `--scheme X` asserts none.
