## B3-L07 — partial only on the explicit load precondition

`B-A02.2-B-R02.1-N2-17-farside-ten-rerun1` otherwise covers the row strongly:
ten of ten exact left-from-element flows pass, every run retains Before/After
PNGs, reveals `Remove from favorites`, and logs the pointer action. The client
logs preserve start `(246,y)`, end `(0,y)`, 15ms path segments, a stationary
250ms hold, and lift, with no shell `input swipe`; the stock favorite control
passes. Exact-head swipe-coordinate tests cover the named geometry.

However, this harness did not generate host load. Its first run records a
one-minute load of 7.37 before and 7.07 after (although longer averages exceed
8), and the row explicitly requires load >=8 generated by the row. Do not
silently grade that precondition from the five-minute average. Smallest
complement: one controlled load inventory proving >=8 across the ten-run
batch, or a binding ruling that the recorded longer load average satisfies the
input. The gesture/runtime work itself need not be repeated absent that
ruling.
