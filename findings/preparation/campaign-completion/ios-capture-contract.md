This is a bounded correction to the initial iOS evidence review, not a new harness project. Existing raw candidate3 evidence and first verdicts remain unchanged. All new-candidate rows run fresh.

Use the already reviewed capture-one command primitive, copied and rebound only after the new candidate manifest exists: exact new binary, manifest/hash, runner home and iOS session. Each command, including inventory and input preparation used to grade a clause, gets argv/cwd/relevant environment/start/end/exit/raw stdout/stderr. The primitive hashes executable, bundle and installed runner. No command-completed auto-pass rule.

For IOS-001 literal name-only ensure, reserve latest installed runtime; observe actual runtime from the returned UUID in inventory. Do not force26 merely because earlier reservation incorrectly assumed it. Explicit runtime rows retain their literal request.

No signal authority follows from a product log. Coverage semantics and ownership race acceptance are separate clauses.

Every row's final verdict maps each expected clause to specific raw evidence. Report before/after protected identity/runtime/state accurately; changing dataPathSize is not proof of owner mutation and means the whole inventory is not byte-identical. No historical metadata fabrication.

Before live use, root/actor inspect only the new candidate binding and the above added capture points. Reuse reviewed common capture logic; no duplicate timeout/process-management implementation or broad re-review. Device reservations remain mandatory and root grants batches, not each command.
