## Controller ruling resolving the extra-slot conflict

Root directed IOS019 immediately after IOS010. It deletes the exact IOS003 Pin generation before IOS011–018, so IOS015 and IOS018 may each use their literal two row extras without exceeding the standing at-most-two-extra rule. This grants no third-extra window and no replacement Pin. Session teardown must still capture membership and exclude both primaries and every unrelated target.

Capacity-session primary records are shutdown-only lifecycle claims. A session teardown that includes either primary is forbidden because it would alter the required restored Booted state. Capacity cleanup uses only recorded targeted shutdown/ensure transitions; it never deletes a primary. The group returns both primaries Booted with frozen app identity restored, extra3 in the state required by the next reservation, and absent plain `cov5-ios-4`.
