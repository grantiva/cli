# New Breakage in the Fix Diff

1. **Important — Ordinary element reads now reject soft step deadlines before reaching the transport.** `pkg/uiautomator2/element.go:265–280,322–338,358–372` routes the existing Text/Attribute/Rect APIs through the new context methods, whose unconditional `ctx.Err()` check treats `DeadlineExceeded` as immediately terminal. This applies even when the context has no HardDeadline marker. It contradicts the existing ordinary-request rule in `transport.go:99–124`: a short step deadline extends neither below nor through the default request floor, and only explicit cancellation or a hard operation must abort it. A normal, non-post-swipe relative-point/long-press tap can find its element after a short soft step deadline but within the allowed HTTP floor, then fail its required Rect read immediately. Before this fix, Rect reached the transport under the same soft context and could succeed. The retained `TestShortStepDeadlineKeepsDefaultFloor` only sends key actions, so it does not cover the changed element methods.

   **Fix:** preserve legacy soft-context behavior in the ordinary element methods; apply expiry rejection only to explicit cancellation or a marked hard operation, consistently with doWithRetry. Audit the new unconditional context-error checks in shared selector helpers (`driver.go:803,1043,1080,1090`) against that same intended distinction. Add an ordinary element/driver regression where a lookup consumes a short soft deadline and subsequent Text/Attribute/Rect still reach the transport under the default floor, plus hard-deadline/cancellation siblings that remain bounded and send no late action. Do not weaken the stable-target hard gate.

2. **Important — Passing stepScope into element detail requests drops the real step context.** `pkg/driver/uiautomator2/driver.go:1087,1094` now unconditionally calls `elem.TextCtx(ctx)` and `elem.RectCtx(ctx)`. The same helper is used by `findElementOnce` at967–968 with `stepScope`, which is deliberately a Background-based sentinel (`wait_crash.go:144–153`), not the active flow/step context. `findOne` and `sourceCtx` already translate that sentinel into the client's ordinary step-scoped methods. The new element calls do not: their HTTP requests use the never-canceled sentinel directly. The real keyboard-settle path `keyboard.go:203–206 → findElementOnce → tryFindElementCtx` therefore loses parent cancellation and any extended step budget for Text/Rect, allowing a blocked detail read to run to the default request timeout after the flow is canceled. Previously `elem.Text()`/`Rect()` used `client.stepContext()` here.

   **Fix:** preserve stepScope/nil dispatch for element details just as findOne/sourceCtx do: use the ordinary element methods when the caller does not own a context, and the context methods for actual wait/hard contexts, or provide one equivalent centralized conversion. Add a production-client regression entering through the stepScope/keyboard-settle path, cancel the active step during a blocked Text or Rect request, and require prompt HTTP cancellation; retain extended ordinary request-budget semantics. This must not replace the explicit per-request contexts used by concurrent Task1 artifact collectors.
